## 1. 测试概述

### 1.1 测试目的

本次测试旨在对 Practice Software Testing — Toolshop 电商工具商店系统的 Sprint 5 with Bugs 版本进行**系统级手工功能测试**，验证系统核心业务功能是否符合预期，发现并记录 UI、功能逻辑、数据交互等层面的缺陷，评估当前版本的质量水平，为后续的缺陷修复与版本迭代提供依据。

### 1.2 测试范围

测试覆盖 Toolshop 系统的以下核心模块：

| 模块 | 覆盖内容 |
| --- | --- |
| **登录模块** | 登录弹窗UI、邮箱/密码输入与校验、登录鉴权、账号锁定机制、密码显隐切换、注册/忘记密码链接跳转、回车快捷登录 |

## 3. 测试方法

### 3.1 整体测试策略

本次测试采用**黑盒手工功能测试**方法，不涉及系统内部代码实现。测试策略为：

1. **需求分析**：基于官方 Bug 清单、Swagger API 文档、UI 原型图进行需求分析与测试点识别
2. **测试设计**：以功能测试为主，从"显示"和"操作"两个维度设计测试点
3. **测试执行**：逐条执行测试用例，记录实际结果，与预期结果对比
4. **缺陷管理**：发现 Bug 后记录详细信息（编号、标题、描述、复现步骤、环境、截图、优先级、严重性）
5. **结果分析**：汇总测试数据，评估质量状态，输出测试报告

### 3.2 测试用例设计方法

| 方法 | 应用场景 |
| --- | --- |
| **等价类划分** | 登录（邮箱有效/无效等价类）、注册（各字段有效/无效等价类）、搜索（有/无匹配结果） |
| **边界值分析** | 密码长度边界（9/10/40/41位）、价格区间边界（1/200）、商品数量边界（10/11） |
| **场景法** | 端到端购物流程（游客加购→登录→结账；已登录用户加购→结账）、注册→登录闭环 |
| **错误推测法** | 特殊字符输入、空值提交、字段绑定颠倒、接口参数缺失 |
| **UI 验证** | 页面布局、文案拼写、图标资源、字体一致性、浏览器兼容性（Chrome/Edge/Firefox） |
| **抓包验证** | 通过 Chrome DevTools Network 面板验证价格筛选接口参数是否完整发送 |

### 3.3 测试执行流程

```
需求分析 → 测试计划 → 测试用例设计 → 测试执行 → 缺陷记录 → 测试报告
```

### 3.4 测试优先级定义

| 优先级 | 定义 | 覆盖内容 |
| --- | --- | --- |
| **P0** | 核心业务功能，必须测试 | 登录/注册/首页导航/商品浏览/加购/购物车结算/支付 |
| **P1** | 重要功能，影响用户体验 | 多筛选叠加/表单校验细节/边界值/异常场景 |
| **P2** | 非核心功能，辅助验证 | UI 样式/文案拼写/浏览器兼容性/无障碍 |

### 6.4 关键发现

1. **支付网关缺失（BUG_030）是最高优先级阻塞问题**：由于支付方式下拉框无法加载任何可选支付渠道，导致所有需要完成下单的端到端流程用例全部阻塞，系统的核心商业闭环 — 用户完成购买 — 完全不可用。

2. **商品选购链路存在多个串联故障**：商品详情页数量调整（BUG_020）+ 购物车删除（BUG_025）+ 金额显示异常（BUG_026）形成"无法选数量 → 删不掉 → 金额看不准"的连续故障链，严重损害购物体验。

3. **价格筛选功能完全失效（BUG_014）**：maxPrice 参数未传递至后端，商品无法按预算区间过滤。对于电商系统而言，价格筛选是用户决策的核心辅助工具，该缺陷直接影响商品发现效率。

4. **注册模块存在安全隐患**：密码最小长度校验失效（BUG_008）+ Country/State 标签绑定颠倒（BUG_007）+ 账号锁定阈值异常（BUG_002），三者叠加使用户身份认证体系的可靠性受到严重挑战。

5. **UI 文案与资源质量偏低**：发现 7 处文案拼写错误、2 处图标破损、多处字号/对齐/宽度不一致的 UI 样式问题，反映出前端细节质量管控不足。

6. **跨浏览器兼容性问题突出**：Chrome 存在 9 个浏览器特异性缺陷（输入框内边距、按钮宽度、Tab 顺序、图片加载等），Edge 和 Firefox 也各自存在问题，表明缺乏系统性的跨浏览器测试。

## 7. 结论与建议

### 7.1 最终结论

**本次测试结论：当前 Sprint 5 with bugs 版本不符合上线标准，不建议发布。**

主要依据：
- 测试用例通过率仅为 **53.5%**，远低于行业常规准入标准（通常 ≥ 95%）
- 存在 **2 个致命缺陷**（价格筛选完全失效 + 支付网关缺失阻塞全部下单流程）
- 存在 **6 个严重缺陷**（导航跳转错误、排序全反、数量调整失效、删除失效等）
- 端到端核心业务流程（用户购买）**完全无法走通**，系统核心商业价值为零
- 注册/登录安全策略存在**多项校验逻辑错误**（密码长度、锁定阈值）

> **说明**：本版本为实训专用带 Bug 版本，预埋 90+ 已知缺陷。本次测试发现的 30 个 Bug 均与官方已知缺陷清单吻合，测试覆盖了官方清单中约 32% 的已知 UI Bug。未测试部分主要涉及：Invoice 页面、Profile 页面、Forgot Password 页面、Contact 页面、Rentals 详情页面、API 层漏洞、无障碍缺陷等。

### 7.3 测试经验总结

1. **等价类划分 + 边界值分析是发现功能 Bug 最有效的方法组合**：本次测试中密码长度校验失效（BUG_008）、数量上限不一致（BUG_023）等关键 Bug 均通过边界值测试发现。
2. **抓包验证是发现前端-后端数据交互缺陷的关键手段**：价格筛选参数缺失（BUG_014）若仅靠 UI 观察难以定位根因，通过 Chrome DevTools Network 面板抓包才发现 maxPrice 参数未发送。
3. **场景法对端到端流程测试不可或缺**：2 条端到端流程用例暴露了支付网关缺失的阻塞性缺陷，单模块测试无法发现此类跨模块串联问题。
4. **跨浏览器测试应系统化执行**：同一页面在 Chrome/Edge/Firefox 上各存在不同缺陷，说明仅进行单浏览器测试会遗漏大量兼容性问题。
